# 功能说明

## 核心：收集 → 排期 → 随时调整

新增事件时日期可留空。所有未排期事件先进入待办池，适合一次录入许多任务后再分配日期。拖到某一天后，它从待办池移入当天安排；跨日期拖动改变日期；拖回待办池则清除排期。列表内的放置位置决定顺序。事件的标题、说明、颜色、完成状态和提醒标记会随移动保留。

电脑保留日期区和事件池的并排工作区。手机在同一页面显示上方日期和下方待办，两个区域可分别滚动；无需在两个互不相见的标签页之间切换。手机只从六点手柄开始拖动，正文用于上下滑动浏览，避免把普通滚动误当成排期。

## 事件与浏览

| 功能 | 行为 |
| --- | --- |
| 新增/编辑 | 名称、完成状态、直接安排日期、颜色、提醒标记、事件说明 |
| 完成 | 点击勾选框切换完成状态，日期显示总数和已完成数 |
| 提醒标记 | 显示感叹号的醒目标记；不是系统通知、邮件、闹钟或定时推送 |
| 调序 | 待办池内、同一天内拖动调整顺序 |
| 操作菜单 | 手机点击“…”打开顶层弹窗，仅编辑、删除；编辑前关闭菜单 |
| 日期导航 | 回到今天、打开日历/选择日期、手机上一周/下一周 |
| 历史回顾 | 手机默认预载过去七天，定位今天；向下拉动回看，顶部继续加载更早日期 |
| 未来安排 | 日期列表向后延展；触摸拖动靠近边缘可滚动目标区域 |
| 外观 | 工作台标题、说明、主色、辅色、背景色；跟随当前工作区数据保存 |
| 备份 | 导出 JSON；导入 JSON 替换当前工作区，需要明确确认 |

## 保存和同步

独立 HTML 的存储键是 `daily_event_workbench_github_share_v1`，使用独立的修改记录合并多窗口操作。不同事件/不同字段可合并；同一内容有冲突时由用户选择。写入失败会保留当前窗口修改并提示重试。文件本身不携带浏览器存储中的事件；复制 HTML 不会复制历史记录。

云端版使用登录用户标识隔离数据库工作区。客户端按变更合并，服务器通过 revision 检查拒绝过期写入；冲突时可导出本机数据、保留本机或加载云端。网络失败时尝试保留本机草稿，重新联网后同步；首次无缓存且离线时阻止把空数据覆盖到云端。同步不是实时协同编辑，其他设备更新通常在定时检查、回到页面或手动同步后显示。

云端请求体当前限制为约 2 MB（实现按字符串长度检查），超出时会提示精简并备份。此工具按日期排期，没有时段日程、重复任务、附件系统或后台通知。相同字段并发修改仍需要人工确认。

## 手机交互更新

为 iPhone 15 Pro 的窄屏与高刷新率场景增加了宽度约束、最小宽度重置、触摸行为与安全区处理。拖动预览使用页面内浮层，移动更新按动画帧合并，缓存目标几何，按经过的时间计算边缘滚动，追加日期时避免整段重绘。实际效果受系统和浏览器影响；自动检查不等同于真机流畅度测试。
