# 部署与恢复

## 从本地备份恢复独立版

解压源码包，打开根目录 `每日事件.html`。在“备份 → 导入备份”选择你另外保存的私人 JSON，确认替换。只恢复源码不会恢复浏览器使用记录；必须有 JSON 或仍可访问的原浏览器存储。

## 云端源码结构

| 路径 | 作用 |
| --- | --- |
| `cloud/app/workbench/document.ts` | 完整工作台 HTML/CSS/JavaScript，作为 JSON 字符串导出 |
| `cloud/app/workbench/route.ts` | 登录检查、注入当前身份、返回私有页面 |
| `cloud/app/api/state/route.ts` | 按用户读写工作区、来源检查、版本并发控制 |
| `cloud/app/chatgpt-auth.ts` | 读取可信托管层提供的登录身份 |
| `cloud/db/schema.ts`、`cloud/drizzle/` | 数据库表结构和迁移 |
| `cloud/worker/`、`cloud/scripts/`、`cloud/vite.config.ts` | Sites/Cloudflare 运行适配及构建工具 |
| `cloud/package-lock.json` | 依赖版本锁定，恢复时使用 npm ci |

这是包含服务端的 Vinext/Cloudflare 应用。GitHub Pages 只能托管静态文件，不能直接运行这里的 API、D1 数据库或登录服务。

## 本地开发检查

需要 Node.js >= 22.13.0 及 npm。在仓库根目录先运行 `node tests/local.cjs`、`node tests/local-mobile.cjs`、`node tests/cloud.cjs`、`node tests/markup.cjs`。这些测试不访问真实账号和真实数据库。

进入 `cloud` 目录：

```sh
npm ci
npm run build
npm run dev
```

开发默认地址为 `http://localhost:5173`，登录入口 `/signin-with-chatgpt?return_to=/workbench`。开发适配器只在本机使用虚构身份，不是正式 ChatGPT OAuth 服务。启动时的开发数据库是独立的本地库，不包含原线上记录。

运行前需要在本地 D1 库执行迁移。开发环境的配置由 Vite 生成，在 `npm run dev` 启动后另开终端找到 `.wrangler/deploy/config.json` 指向的 Wrangler 配置；使用对应配置对 `DB` 执行本地迁移，例如：

```sh
npx wrangler d1 execute DB --local --config <生成的配置文件路径> --file drizzle/0000_petite_luckman.sql
```

该 SQL 用于新空库，只执行一次。不要在含有数据的正式库盲目重放建表或导入。配置生成位置与依赖版本有关，应以实际生成的配置为准。

## 通过 Sites 恢复上线

使用 Sites 的新项目流程，以 `cloud/` 为源码创建新的网站，并启用绑定名为 `DB` 的 D1 数据库；由平台生成新的站点身份和凭据，再执行数据库迁移与构建发布。`.openai/hosting.json` 只保留通用的 `d1: DB` 配置，故意不携带原私有站点的 `project_id`。

登录依赖 Sites 可信网关注入的 `oai-authenticated-user-*` 请求头。正式部署必须由可信网关剥离外部伪造头并完成身份验证，且不能让公网绕过网关直接访问后端。自托管到其他平台时，必须替换为该平台的真实会话认证及数据库绑定；仅保留这些头读取代码不构成安全登录。

迁移只创建空表，不含种子事件和用户记录。发布成功后，使用自己的账号登录，在页面导入私人 JSON，等待同步完成，再用另一设备同账号核对。云端的用户标识来自登录服务，更换身份服务或站点不保证旧标识相同，JSON 导入是应用层的数据恢复方式。

本备份保留源码和锁文件，不包含依赖目录、已编译产物、生产数据库和部署凭据。未来平台接口变化或依赖服务停止时可能需要调整；保存源码不等于永久保留托管服务。

## 校验备份

`SHA256SUMS.txt` 列出源码及文档的 SHA-256（不含清单自身）。在 PowerShell 使用 `Get-FileHash -Algorithm SHA256 文件路径`，与相应清单行比较。清单对应本次归档快照；后续修改文件后校验值会不同。
